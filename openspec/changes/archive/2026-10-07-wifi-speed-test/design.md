# Design

## Context

RouterApp currently presents local link metrics (negotiated Wi-Fi downlink rate and Ethernet link speed reported by the TP-Link router for connected clients). However, users cannot benchmark their actual internet and Wi-Fi throughput.
The app consists of two modules:
- `:protocol`: A Kotlin JVM library providing the router communication layer, TR-181 schema catalog, and OkHttp client.
- `:app`: An Android application with Jetpack Compose Material 3 UI.

The goal is to provide an integrated speed test screen in RouterApp using a lightweight, reliable, and unauthenticated public edge service.

## Goals / Non-Goals

**Goals:**
- Provide client-side Wi-Fi and internet speed testing with zero new third-party dependencies, leveraging existing OkHttp and Kotlin Coroutines.
- Benchmark round-trip latency (ping ms), jitter (ms), download speed (Mbit/s), and upload speed (Mbit/s).
- Stream real-time test progress (progress 0..1, phase, instantaneous throughput) to Compose UI.
- Provide a dedicated Compose screen with interactive controls (Start / Stop), gauges/meters, and a summary of completed metrics.
- Integrate the screen as a custom page in `Catalog.pages` under `Group.STATUS` with complete Spanish localization.

**Non-Goals:**
- Running TR-143 diagnostics or iperf on the router hardware itself (the XGB430v Pro `user` account lacks privileges for firmware-level diagnostics).
- Heavy proprietary speed test SDKs requiring API keys, licenses, or ad banners.
- Extended continuous load testing or multi-minute stress tests.

## Decisions

### 1. Speed Test Service: Cloudflare Speed Test (`speed.cloudflare.com`)
- **Choice**: Use Cloudflare's public speed test HTTP endpoints:
  - Latency / Jitter: `GET https://speed.cloudflare.com/__down?bytes=0`
  - Download: `GET https://speed.cloudflare.com/__down?bytes={size}` (e.g. 10MB to 25MB streams)
  - Upload: `POST https://speed.cloudflare.com/__up`
- **Rationale**:
  - Globally distributed Anycast CDN edge with high throughput and low server-side latency worldwide.
  - Publicly accessible over standard HTTPS without authentication tokens, API keys, or registration.
  - Straightforward HTTP semantics that can be cleanly driven using OkHttp and Kotlin Coroutines.
- **Alternatives considered**:
  - *LibreSpeed public instances*: Inconsistent server uptime, variable capacity, and hardcoded third-party domain dependencies.
  - *Fast.com (Netflix)*: Requires reverse-engineered token scrapers that Netflix updates without warning.
  - *NDT7 / M-Lab*: Requires WebSocket implementation and locating services, increasing complexity without noticeable benefit.

### 2. Architecture and Module Boundaries
- **Choice**:
  - Place `SpeedTestEngine`, `SpeedTestState`, and `SpeedTestResult` in `:protocol` (`es.routerapp.protocol.speedtest`), keeping network benchmark logic decoupled from Android UI.
  - Place `SpeedTestScreen` in `:app` (`es.routerapp.app`), styled with Material 3 Expressive components matching `StatusScreens.kt`.
  - Add `Page(id = "speedtest", title = "Speed test", group = Group.STATUS, custom = true)` to `Catalog.pages`.
  - Add Spanish translations to `SpanishTexts.kt` to satisfy `CatalogI18nTest`.
- **Rationale**: Keeps business logic testable on the JVM without Android emulator dependencies and conforms to RouterApp's catalog architecture.

### 3. Benchmark Execution Algorithm
- **Ping & Jitter**: Run 5 sequential HEAD/GET requests with 0 bytes. Calculate average RTT as ping latency. Calculate mean absolute difference between successive RTT measurements as jitter:
  $$\text{Jitter} = \frac{1}{N-1} \sum_{i=1}^{N-1} |RTT_{i+1} - RTT_i|$$
- **Download**: Stream bytes from Cloudflare's endpoint using OkHttp `ResponseBody.byteStream()`. Buffer read in 16KB chunks. Every 100ms, compute instantaneous Mbit/s over the sampling window and overall Mbit/s. Target test duration is 5-7 seconds or until payload completes.
- **Upload**: Stream generated byte payloads via OkHttp `RequestBody`. Track bytes written in `writeTo(sink)` and sample elapsed time. Target test duration is 5-7 seconds.

### 4. Cancellation and Lifecycle
- Coroutine-based cancellation: If the user leaves the screen or taps "Stop", cancelling the active coroutine job immediately closes OkHttp sockets and resets state to idle.

## Risks / Trade-offs

- **[Risk] High mobile data consumption if user is accidentally not on Wi-Fi**
  → *Mitigation*: Limit total transfer volume to ~35MB per full run (25MB down, 10MB up) and clearly display Wi-Fi SSID / connection state on screen.
- **[Risk] Network timeouts or firewall blocking CDN endpoints**
  → *Mitigation*: Configure conservative OkHttp timeouts (10s connect, 15s read) and surface clear failure states with retry buttons.
- **[Risk] UI rendering jank during heavy network I/O**
  → *Mitigation*: Execute all socket and buffer reading on `Dispatchers.IO` and throttle progress emissions via `conflate` / 100ms windowing before publishing to UI state.
